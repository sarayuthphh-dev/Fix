# เปิดใช้งานลิงก์อีเมลสำหรับผู้ติดต่อ

สถานะ ณ 27 พฤศจิกายน 2569: โฮสต์เชื่อม Supabase Auth แล้ว และปุ่มรับลิงก์เปิดให้ทดสอบ ยังต้องตรวจรับลิงก์อีเมลจริงและตั้ง custom SMTP สำหรับผู้ติดต่อสหกรณ์ก่อนประกาศใช้งานทั่วไป การแจ้งปัญหาทั่วไปไม่ต้องใช้บริการนี้

## ตั้งค่าครั้งแรก

1. ติดตั้งและเชื่อม Supabase เพื่อเลือกหรือสร้างโครงการที่จะใช้กับระบบนี้
2. เปิด Email provider ใน Supabase Authentication
3. กำหนด Site URL เป็น URL เว็บไซต์จริง และเพิ่ม redirect URL แบบตรงตัว: `https://cad-support-desk-nov26.sarayuthphh.chatgpt.site/auth/finish`
4. ใช้แม่แบบอีเมลที่มี `{{ .ConfirmationURL }}` เพื่อให้ Supabase ยืนยันลิงก์และส่งกลับด้วย authorization code (PKCE) ไม่เปลี่ยนไปใช้ URL ที่รับ access token ใน fragment
5. ตั้ง custom SMTP สำหรับส่งอีเมลถึงผู้ติดต่อจริง ตรวจโดเมนผู้ส่งและข้อจำกัดปริมาณส่งให้เหมาะกับจำนวนสหกรณ์ บริการส่งอีเมลเริ่มต้นของ Supabase มีข้อจำกัดและไม่ควรใช้เป็นช่องทางหลักสำหรับผู้ใช้จำนวนมาก
6. ตั้ง runtime variables ใน Sites: `SUPABASE_URL` และ `SUPABASE_ANON_KEY` โดยใช้ publishable/anon key ไม่ใช้ service-role key ตั้ง `PUBLIC_APP_ORIGIN` ให้ตรงกับ URL จริง แล้ว deploy เพื่อใช้ค่าล่าสุด
7. เพิ่มผู้ติดต่อในทะเบียน ตรวจสอบกับสหกรณ์แล้วอนุมัติ ปุ่มขอลิงก์จะส่งเฉพาะอีเมลที่มีสิทธิ์สหกรณ์ที่ยังเปิดใช้งาน
8. ทดสอบรับลิงก์จริงด้วยผู้ติดต่ออย่างน้อยสองสหกรณ์ และตรวจว่าอ่าน/ดาวน์โหลดข้อมูลข้ามสหกรณ์ไม่ได้ ก่อนประกาศเปิดใช้การเข้าสู่ระบบด้วยอีเมล

ตัวแปร `emailLoginReady` หมายถึงตั้งค่า URL/key ครบเท่านั้น ไม่ใช่หลักฐานว่าการส่งอีเมลจริงผ่านแล้ว

หากเปิดแจ้งเตือน LINE และเลือกแชทส่วนตัวที่ทดสอบแล้ว ระบบเริ่มแจ้งทันทีเมื่อรับการกดขอลิงก์ที่ผ่านการตรวจรูปแบบอีเมลและจำกัดความถี่ โดยไม่รอ Supabase และไม่ขึ้นกับสถานะอนุมัติ การส่งลิงก์และสิทธิ์เข้าถึงยังตรวจตามเดิม อีเมลในข้อความถูกปิดบังบางส่วน ไม่ส่งลิงก์ รหัส หรือ session token ไป LINE ผู้ดูแลดูผลได้ในหน้าตั้งค่า LINE การแจ้ง LINE ล้มเหลวไม่ทำให้การขอลิงก์อีเมลล้มเหลว

## ประสบการณ์ผู้ใช้

ผู้ติดต่อกรอกอีเมลแล้วเปิดลิงก์ด้วยเบราว์เซอร์และอุปกรณ์เดียวกับที่ขอ ระบบใช้ PKCE ป้องกันการนำ authorization code ไปใช้ในเบราว์เซอร์อื่น token อยู่ในคุกกี้ HttpOnly / Secure / SameSite=Lax และไม่ส่ง token กลับใน JSON ของหน้าเว็บ ไม่มีการเก็บ token ใน localStorage

การยืนยันอีเมลไม่ได้ให้สิทธิ์เข้าถึงสหกรณ์โดยอัตโนมัติ ต้องมีทะเบียนผู้ติดต่อสถานะ active และสหกรณ์ active ทุกครั้งที่เรียก API การถอดสิทธิ์จึงมีผลแม้ session ยังไม่หมดอายุ ส่วนสิทธิ์เจ้าหน้าที่รับเฉพาะ identity จาก Sites / ChatGPT ร่วมกับ allowlist/ทะเบียนเจ้าหน้าที่ฝั่งเซิร์ฟเวอร์

ผู้ที่ไม่สะดวกใช้ลิงก์อีเมลยังเลือกเข้าสู่ระบบด้วย ChatGPT ที่ใช้อีเมลตรงกับทะเบียนได้ หลังผู้ดูแลอนุมัติแล้ว
