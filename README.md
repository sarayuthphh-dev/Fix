# CAD Support

ระบบแจ้งปัญหาการใช้งานโปรแกรมกรมตรวจบัญชีสหกรณ์ หน้าจอภาษาไทย รองรับคอมพิวเตอร์และมือถือ

## ความสามารถ

- รับเรื่อง 2 ประเภท: แจ้งปัญหา และขอแก้ไข พร้อมโปรแกรม หมวดหมู่ ความเร่งด่วน และข้อมูลผู้แจ้ง
- รองรับ 4 โปรแกรม: ระบบบัญชีแยกประเภท ระบบเงินรับฝาก ระบบสินค้า และระบบสมาชิกและหุ้น
- ออกเลขอ้างอิงอัตโนมัติ บันทึกถาวรด้วย Cloudflare D1
- แนบภาพ PNG/JPG/WEBP หรือ PDF สูงสุด 3 ไฟล์ ไฟล์ละ 5 MB จัดเก็บใน R2
- ติดตาม 4 สถานะ มอบหมายผู้รับผิดชอบ แสดงความคิดเห็น และดูประวัติการดำเนินงาน
- ป้องกันการแก้ไขทับข้อมูลที่มีผู้อื่นเปลี่ยนแปลงแล้ว ด้วยการตรวจรุ่นข้อมูล
- ค้นหา กรอง แบ่งหน้า ส่งออก CSV พร้อมป้องกันสูตรในสเปรดชีต
- แดชบอร์ด กราฟแนวโน้ม 7/30 วัน และรายงานแยกประเภท โปรแกรม และความเร่งด่วน
- คลังคำแนะนำทั่วไปและข้อมูลผู้แจ้งเริ่มต้นบนอุปกรณ์
- ข้อมูลตัวอย่างแยกจากฐานข้อมูลจริง การเปลี่ยนแปลงตัวอย่างไม่ถูกบันทึก

## การเข้าถึง

เผยแพร่เป็นเว็บไซต์ส่วนตัวสำหรับเจ้าของเว็บไซต์ ใช้การเข้าสู่ระบบของ Sites / ChatGPT ทุก API ตรวจตัวตนฝั่งเซิร์ฟเวอร์ การเปิดให้ใช้งานทั้งหน่วยงานยังต้องเพิ่มการจัดการสมาชิกและบทบาท ก่อนเปลี่ยนการเข้าถึงเว็บไซต์

รายชื่อโปรแกรมและประเภทเรื่องกำหนดร่วมกันที่ `lib/ticket-options.ts` ทั้งแบบฟอร์มและการตรวจสอบฝั่งเซิร์ฟเวอร์ใช้รายการเดียวกัน รายการเดิมคงชื่อโปรแกรมตามที่บันทึกไว้และยังดูย้อนหลังผ่านตัวกรองและรายงานได้ ระบบนี้ไม่ได้เชื่อมต่อฐานข้อมูลหรือบัญชีผู้ใช้ของกรมฯ และไม่ได้ส่งอีเมลแจ้งเตือนอัตโนมัติ การแจ้งเตือนในหน้าจอแสดงรายการที่รอรับเรื่องหรือรอข้อมูลเพิ่มเติม

## พัฒนาในเครื่อง

ต้องมี Node.js 22.13 ขึ้นไป และ Git

1. ติดตั้งแพ็กเกจด้วยตัวช่วย `install-dependencies.mjs` ของ Sites หรือ `npm run install:ci`
2. สร้าง artifact ด้วย `npm run build`
3. ใช้คำสั่งด้านล่างเพื่อสร้างตารางในฐานข้อมูลท้องถิ่นครั้งแรก จากนั้นใช้ migration `drizzle/0001_chilly_wasp.sql` ที่เพิ่มประเภทเรื่องด้วย (ใช้แต่ละ migration ครั้งเดียว)
4. เริ่มด้วย `npm run dev` แล้วเปิด URL ที่ปรากฏ
5. เข้า `/signin-with-chatgpt?return_to=/` บน localhost เพื่อลงชื่อเข้าใช้บัญชีจำลองสำหรับพัฒนา

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_unique_ink.sql
```

ฐานข้อมูลท้องถิ่นแยกจากข้อมูลจริงบนเว็บไซต์ ห้ามส่ง `.wrangler/`, `.env*`, `.sites-runtime/` และข้อมูลรับรองเข้า source control

## ตรวจสอบ

```sh
npx tsc --noEmit
npm run build
node scripts/verify-browser.mjs
```

การทดสอบเบราว์เซอร์ใช้ Chrome และ `playwright-core` โดยตั้ง `PLAYWRIGHT_MODULE_PATH` หากโมดูลอยู่ภายนอกโครงการ และ `CHROME_PATH` หากใช้ตำแหน่งเบราว์เซอร์อื่น รันทดสอบกับ dev server ที่ `127.0.0.1:5173` เท่านั้น สคริปต์สร้างรายการทดสอบในฐานข้อมูลท้องถิ่น และบันทึกภาพใน `outputs/` ซึ่งไม่ถูกส่งขึ้นเว็บไซต์

ครอบคลุมการเข้าสู่ระบบ การแยกข้อมูลตัวอย่าง ค้นหา แบ่งหน้า ตัวกรอง สร้างเรื่อง แนบและดาวน์โหลดไฟล์ มอบหมายผู้รับผิดชอบ เปลี่ยนสถานะ ความคิดเห็น ประวัติ ตรวจความขัดแย้ง ปฏิเสธคำขอข้ามเว็บไซต์ ตรวจรูปแบบข้อมูล การคงอยู่หลังโหลดใหม่ ส่งออก CSV คลังความรู้ รายงาน การตั้งค่า และหน้าจอมือถือ

## โครงสร้างหลัก

- `app/dashboard.tsx`: พื้นที่ทำงานหลัก
- `app/ticket-dialogs.tsx`: แบบฟอร์มและรายละเอียดปัญหา
- `app/ticket-table.tsx`: ค้นหา กรอง แบ่งหน้า และส่งออก
- `app/components.tsx`: กราฟ สรุปสถานะ และหน้าต่างโต้ตอบ
- `app/api/tickets/`: API บันทึกและจัดการเรื่อง พร้อมดาวน์โหลดไฟล์
- `db/schema.ts` และ `drizzle/`: โครงสร้างฐานข้อมูลและ migration
- `.openai/hosting.json`: Site identity และ bindings `DB` / `BUCKET`

การเผยแพร่ใช้ Sites workflow เพื่อสร้าง artifact ส่ง source และใช้ migration บนโฮสต์ ก่อน deploy โดยคงการเข้าถึงแบบส่วนตัว
